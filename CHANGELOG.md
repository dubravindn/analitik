# CHANGELOG

Изменения по этапам ТЗ «от отчётника к аналитику».

## Из аудита исключены только списания

- Изменения и удаления приёмок, платежей, расходных ордеров и торговых документов
  остаются в управленческом отчёте; документы списания не загружаются.
- Для заказов покупателей и отгрузок сохранён точечный контроль: изменение даты
  (включая документы прошлых дат) и снижение фактической цены ниже «Налички».

## Инвентаризации по точкам

- В управленческий PDF добавлен отдельный раздел по четырём собственным точкам:
  дата инвентаризации, номера документов, списание, оприходование и чистая
  корректировка учёта.
- Обычная ежедневная порча розницы не смешивается с инвентаризацией: учитываются
  связанные технические корректировки; правило БАЗЫ сохранено.
- Показана только доказуемая причина из документа. При её отсутствии отчёт и ИИ
  дают проверяемые гипотезы, но не выдают их за установленный факт.
- ИИ получает отдельные факты по недостаче/излишку и сигнал, если за последние
  семь дней инвентаризация не найдена хотя бы на одной точке.

## Полный аудит за многодневный период

- Журнал заказов и отгрузок читает отдельное окно последних 100 событий каждого дня и типа:
  насыщенный последний день больше не вытесняет важные изменения из начала недели.
- Детали событий загружаются последовательно, чтобы не превышать лимит read-only
  API МойСклад и не терять раздел из-за ответов 429.

## Точечный аудит заказов и отгрузок

- По заказам покупателей и отгрузкам показываются только изменения дат и снижения
  фактической цены позиции ниже действующей цены «Наличка».
- При сравнении цены учитывается скидка строки; добавление/удаление товара, количество,
  резерв, статус и прочие технические правки скрыты.
- Отгрузка попадает в отчёт по дате самого изменения в журнале, поэтому видны и правки
  отгрузок, оформленных прошлыми датами.

## Скидка поставщика в топе товаров

- В отдельных топах товаров по складам закупочная стоимость товаров
  ООО «Поставщик» теперь уменьшается на 7% (`× 0,93`).
- Валовая прибыль каждого товара теперь сходится с финансовой сводкой отчёта,
  где эта скидка уже учитывалась.

## Аудит заказов покупателей

- Раздел «Изменённые и удалённые документы» теперь читает официальный журнал
  `/audit` МойСклад для заказов покупателей и показывает номер заказа, время и
  фактического пользователя, выполнившего изменение.
- Для даты, плановой доставки, статуса, суммы, склада, проекта, клиента и
  состава заказа выводятся реальные значения «было → стало»; удалённые заказы
  также раскрываются по позициям.
- Одинаковые массовые изменения группируются с сохранением всех номеров
  документов; пустые технические события и дубли скрываются. При большом
  объёме показываются последние 100 значимых событий.

## Закрытая группа руководителей

- Общее меню стало двухуровневым: сначала руководитель выбирает «Аналитика»
  или «Работа сотрудников», затем видит кнопки только выбранного раздела.
- При отключённом Telegram Group Privacy аналитик молча пропускает кнопки
  сотрудников и посторонние сообщения; свободный вопрос принимается только
  после кнопки AI или как прямой ответ сообщению `@CBDanalitik_bot`.
- Аналитик поддерживает одну разрешённую Telegram-группу и отдельно проверяет
  ID группы и ID руководителя; другие группы и участники игнорируются.
- Добавлены адресные групповые команды `/menu`, `/ask`, `/period`, `/today` и
  `/forecast`, общее меню с ботом сотрудников `@CBDOt4et_bot` и общий контекст
  AI-вопросов внутри группы.
- Пошаговые PDF-диалоги изолированы по руководителю, поэтому одновременный
  выбор периода Дмитрием и Николаем не смешивается.

## AI-собеседник — Telegram Q&A

- Любое свободное сообщение разрешённого пользователя превращается в
  read-only бизнес-вопрос; добавлена видимая кнопка `🧠 Спросить ИИ`.
- Период распознаётся по-русски, уточняющие вопросы наследуют период последних
  четырёх live-ответов только своего chat_id.
- Факты охватывают продажи, три уровня прибыли, склады, товары, расходы,
  списания, приёмки, перемещения, клиентов, остатки и последний NEW-прогноз.
- Числа AI сверяются не со всем контекстом, а только с явно процитированными
  `fact_id`; в Telegram выводится серверный блок подтверждений.
- Финансовые факты используют ту же `_period_metrics`, скидку поставщика и
  формулы, что утверждённый production PDF. Q&A не меняет документы и не
  запускает тяжёлые синки/forecast.

## AI-аналитик — shadow rollout

- После PDF «Отчёт за период», «Состояние на сегодня» и прогноза создаётся
  фоновое AI-задание; отправка PDF не ждёт модель.
- Анализ выполняет Codex CLI по подписке ChatGPT под отдельным Linux-пользователем,
  без API-ключа и без доступа к токенам Telegram/МойСклад или паролю БД.
- Добавлены структурированные факты, детерминированные правила аномалий, строгая
  JSON Schema, проверка `fact_id`, максимум пять выводов и безопасный fallback.
- Добавлены журнал `ai_analysis_run`, обратная связь 👍/👎 и ежедневный запуск
  в 08:30 МСК с `Persistent=true`.
- Production начинает с `AI_ANALYST_MODE=shadow`: результаты сохраняются, но не
  отправляются владельцу до семидневной проверки качества.

## Этап 0 — достоверность данных (ветка `etap-0-dostovernost`)

### Блок J — правки по проверке бота владельцем (05.08)

- **J1 Продажи.** Методика прибыли в шапке — полными словами, без сокращений;
  пометка Слободского (опт+розница через одну кассу) вынесена отдельными строками
  под цифрами; блок «Топ-10 по прибыли» убран (прибыль есть в топ-20 по выручке).
- **J5 Перемещения.** Убран «Топ-10 перемещаемых товаров».
- **J3 Аудит.** Плоский список «тип · дата · склад · сумма · кто»; внятное
  сообщение при отсутствии правок; исправлена детекция изменённых (datetime, порог
  2 мин); добавлена секция «9. Изменения и удаления» в PDF.
- **H2.3 Оприходования.** Таблицы `enter_doc`/`enter_item`, ETL `etl_enter`
  (`/entity/enter`), команда `sync-enter`, синк в daily/backfill.
- **J2 Инвентаризация Базы.** Отдельный блок в списаниях: списано vs оприходовано,
  итог корректировки со знаком, документы обеих сторон с позициями.
- **J4 Прогноз.** Полностью переструктурирован в пять блоков (что заказано →
  заказано минус остаток → прогноз спроса → итого к заказу на фургон → что брать
  не надо). Формула «к заказу» = прогноз спроса (продажи прошлой недели) + заказы
  − остаток, округление до упаковки (СРЕЗКА); списания больше не входят.

### Дозакрытие блока I (прежние приоритеты)

- **I5 Расходы.** Дерево «статья расходов → документы по убыванию суммы»;
  «по складам» сведено к компактной сводке (≤5 строк).
- **H3 Качество цен.** Новый отчёт/кнопка «🏷 Цены»: доля товаров без закупочной
  цены, приоритетный список продаваемых без цены, аномалии «Наличка ниже закупа».
- **I4 Списания.** Две цены (закуп + нал) в позициях, итог двумя суммами, убрана
  разбивка «по проектам».
- **I8 Перемещения.** Наличная цена в позициях и фильтр «Ассортимент» (сводка,
  потоки, документы).
- **I9.** «Топ-N» по фактическому числу строк; строка покрытия закупочными
  ценами добавлена в списания.

- **Расходы — фильтр по складу.** Диалог расходов в боте получил шаг выбора
  склада (фильтр по `project_name`). «Все склады» показывают ВСЕ расходы,
  расходы без проекта выделены группой «⚠️ Без проекта» — итог сходится с ДДС.
- **Перемещения (новое).** Таблицы `move_doc`/`move_item`, ETL `/entity/move`,
  отчёт (потоки откуда→куда, входящие/исходящие по складу), кнопка
  «🔄 Перемещения», команды `sync-move`/`report-move`, секция в PDF.
- **«Прибыль» → «Прибыль от продаж».** Показатель честно подписан:
  выручка − себестоимость, без учёта расходов и списаний. Формула не изменена.
- **Отток клиентов.** Подписано, что детектор считает по последним 180 дням
  независимо от выбранного периода; при отсутствии — «отставших не обнаружено».
- **Аудит.** Разбивка изменённых/удалённых документов по складу
  (`store`/`project`).
- **Telegram.** Длинные сообщения (>4096) разбиваются по границам строк.
  Списания и перемещения в боте ограничены 50 документами (полный список — в PDF).
- **PDF.** Добавлены секции 6.Клиенты, 7.Прогноз, 8.Перемещения (всего 8).
- **daily.** Синкает ВСЕ сущности за вчера (продажи, остатки, списания, ДДС,
  клиенты, поставки, перемещения) через изолированный try/except — раньше часть
  данных наполнялась только по кнопкам, что давало дыры в истории.
- **⚠️ Таймзоны (МСК).** ETL раньше помечали `moment` (московское время без зоны)
  как UTC. Теперь используется `config.MSK` (UTC+3), «сегодня» считается по Москве
  (`config.msk_today()`). **Существующие данные в БД не мигрированы** — сдвиг
  затрагивал только поле `moment` (поле `day` везде корректно). При необходимости
  точных временных меток за прошлые периоды — перезапустить соответствующий sync
  (ETL идемпотентны, ON CONFLICT DO UPDATE обновит `moment`).
