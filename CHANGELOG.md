# CHANGELOG

Изменения по этапам ТЗ «от отчётника к аналитику».

## Этап 0 — достоверность данных (ветка `etap-0-dostovernost`)

- **Расходы — фильтр по складу.** Диалог расходов в боте получил шаг выбора
  склада (фильтр по `project_name`). «Все склады» показывают ВСЕ расходы,
  расходы без проекта выделены группой «⚠️ Без проекта» — итог сходится с ДДС.
- **Перемещения (новое).** Таблицы `move_doc`/`move_item`, ETL `/entity/move`,
  отчёт (потоки откуда→куда, входящие/исходящие по складу), кнопка
  «🔄 Перемещения», команды `sync-move`/`report-move`, секция в PDF.
- **«Прибыль» → «Прибыль от продаж».** Показатель честно подписан:
  выручка − себестоимость, без учёта расходов и списаний. Формула не изменена.
- **Отток клиентов.** Подписано, что детектор считает по последним 180 дням
  независимо от выбранного периода; при отсутствии — «отставших не обнаружено».
- **Аудит.** Разбивка изменённых/удалённых документов по складу
  (`store`/`project`).
- **Telegram.** Длинные сообщения (>4096) разбиваются по границам строк.
  Списания и перемещения в боте ограничены 50 документами (полный список — в PDF).
- **PDF.** Добавлены секции 6.Клиенты, 7.Прогноз, 8.Перемещения (всего 8).
- **daily.** Синкает ВСЕ сущности за вчера (продажи, остатки, списания, ДДС,
  клиенты, поставки, перемещения) через изолированный try/except — раньше часть
  данных наполнялась только по кнопкам, что давало дыры в истории.
- **⚠️ Таймзоны (МСК).** ETL раньше помечали `moment` (московское время без зоны)
  как UTC. Теперь используется `config.MSK` (UTC+3), «сегодня» считается по Москве
  (`config.msk_today()`). **Существующие данные в БД не мигрированы** — сдвиг
  затрагивал только поле `moment` (поле `day` везде корректно). При необходимости
  точных временных меток за прошлые периоды — перезапустить соответствующий sync
  (ETL идемпотентны, ON CONFLICT DO UPDATE обновит `moment`).
