# Hermes — аналитика по МойСклад

Сервис для «Цветочной Базы Дубравиных». Читает данные из МойСклад (**только чтение**),
кэширует их в PostgreSQL и считает детерминированные отчёты. Без обращений к языковым
моделям в рантайме — цифры воспроизводимы.

## Что уже умеет (этап 1, приоритет 1 — Аналитик продаж)

По каждой точке и суммарно за день: **выручка, себестоимость, грязная прибыль и её %,
число чеков, средний чек**, топ товаров по выручке. Разрез по каналам: розница
(3 магазина), опт (База), ресторан (СОБРАНИЕ).

### Формулы

| Показатель | Формула |
|---|---|
| Грязная прибыль | Выручка − Себестоимость |
| % грязной прибыли | Грязная прибыль / Выручка |
| Средний чек | Выручка / Число чеков |

Деньги внутри системы хранятся в **копейках** (целые числа), в рубли переводятся
только при выводе — чтобы не терять копейки на округлении.

### Откуда берутся данные

- **Выручка, себестоимость, прибыль, товары** — отчёт МойСклад «Прибыльность по товарам»
  (`/report/profit/byproduct`) с фильтром по складу.
- **Число чеков** — количество документов «Отгрузка» (`demand`) по складу за день.
- Розница/опт/ресторан определяются по складу (см. `STORE_CHANNELS` в `hermes/config.py`).

> ⚠️ **Про себестоимость.** Там, где в МойСклад не проставлена закупочная цена,
> прибыль будет искажена. Отчёт помечает точки, где ≥10% позиций без себестоимости.
> Для группы СРЕЗКА себестоимость достоверна (закуп ставится в приёмке).

## Как запустить руками

```bash
python -m hermes whoami                              # проверить доступ к МойСклад
python -m hermes init-db                             # создать таблицы
python -m hermes sync --from 2026-08-01 --to 2026-08-04   # выгрузить продажи
python -m hermes report --date 2026-08-04            # отчёт за день
```

Конфигурация — в `.env` (шаблон в `.env.example`). Секреты в git не попадают.

## Первичная прогрузка истории (backfill)

Разовая помесячная загрузка истории (продажи, клиенты+возвраты, списания, ДДС,
поставки, перемещения) от старого месяца к новому:

```bash
python -m hermes backfill --months 12      # за последние 12 месяцев (по умолчанию)
```

- **Запускать вручную и лучше ночью** — щадящий режим с паузой 7 с между месяцами,
  но нагрузка на МойСклад заметная.
- **Идемпотентно и с продолжением.** Каждый успешный месяц отмечается в `sync_log`;
  при повторном запуске уже прогруженные месяцы пропускаются — можно смело
  перезапускать после обрыва.
- **Оценка времени:** ~1 минута на месяц данных (зависит от объёма). 12 месяцев —
  ориентировочно 12–20 минут.
- По завершении в лог выводится сводка: число строк и период покрытия по каждой
  таблице.

## Бэкап и восстановление БД

Ежедневный бэкап делает `hermes-backup.timer` (04:30 UTC, до daily-отчёта):
`pg_dump` → `/opt/hermes/backups/hermes_YYYY-MM-DD.sql.gz`, хранятся последние 14.

Ручной бэкап:

```bash
sudo systemctl start hermes-backup.service      # или напрямую:
sudo -u hermes /opt/hermes/app/deploy/hermes-backup.sh
```

**Восстановление из бэкапа** (DATABASE_URL берётся из `/opt/hermes/.env`):

```bash
gunzip -c /opt/hermes/backups/hermes_2026-08-05.sql.gz | psql "$DATABASE_URL"
```

## Тесты

```bash
pytest
```

Тесты покрывают расчётные формулы известными ответами (сверка с реальным днём 2026-08-04).

## Архитектура

```
hermes/
  config.py        конфигурация из .env + справочник складов
  moysklad.py      клиент МойСклад (ТОЛЬКО GET — писать физически нечем)
  db.py            PostgreSQL (psycopg 3), идемпотентные upsert'ы
  schema.sql       таблицы: sales_by_store_day, sales_by_product_day, sync_log
  etl_sales.py     выгрузка продаж в БД
  calc.py          чистые расчётные функции (покрыты тестами)
  report_sales.py  сборка текста отчёта по шаблону
  cli.py           команды: whoami, init-db, sync, report
```

Данные выгружаются в БД по расписанию, отчёты считаются по локальной БД — API не дёргается
на каждый запрос. Повторная выгрузка за тот же день перезаписывает данные, не дублирует.
