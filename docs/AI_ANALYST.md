# AI-аналитик Hermes

AI — дополнительный слой после детерминированного отчёта. Он не участвует в
формировании PDF, не меняет данные МойСклад и не оформляет заказы.

Помимо автоматических сводок, в `live` бот принимает свободные вопросы обычным
текстом. Кнопка `🧠 Спросить ИИ` только показывает подсказку: командный синтаксис
не обязателен.

## Поток данных

1. Бот отправляет существующий PDF без ожидания AI.
2. `analysis_payload.py` собирает структурированные факты из тех же расчётов.
3. `anomaly_rules.py` отмечает обязательные проверяемые сигналы.
4. Бот кладёт JSON-задание в `/var/lib/hermes-ai/spool/jobs`.
5. Изолированный пользователь `hermes-ai` запускает `codex exec` в sandbox
   `read-only`, с авторизацией подписки ChatGPT из собственного `CODEX_HOME`.
6. Ответ проверяется по JSON Schema и по существованию каждого `fact_id`.
7. Бот сохраняет результат в `ai_analysis_run`. В режиме `live` отправляет
   максимум пять наблюдений и кнопки полезности.

## Свободные вопросы

`ai_question.py` определяет период (сегодня, вчера, текущая/прошлая неделя,
месяц, год, явные даты) и собирает фиксированный read-only набор фактов:

- выручка и три уровня прибыли по той же методике, что production PDF;
- сравнения день/неделя/месяц/год и история сопоставимых месяцев;
- склады и топ товаров по выручке;
- расходы, списания, приёмки и перемещения по цене «Наличка»;
- клиенты БАЗЫ и возможный отток;
- актуальный снимок остатков, нули, минусы и залежалые;
- последний рассчитанный NEW-прогноз и его дата.

Для уточняющих вопросов используются последние четыре **live**-ответа этого же
chat_id. Shadow-тесты и разговор другого разрешённого пользователя в контекст не
попадают.

Ответ вопроса проходит отдельную схему `ai_question_output_schema.json`.
Сервер проверяет, что каждый `fact_id` существует, а каждое число встречается
именно в процитированных фактах. В Telegram внутренние идентификаторы скрываются;
вместо них бот добавляет короткий блок «Подтверждение» с периодом и цифрами.

Если последний прогноз относится к старому горизонту, бот обязан сказать, что
актуальных данных для заказа недостаточно. Q&A не запускает тяжёлый forecast и
не заменяет кнопку состояния/прогноза.

В AI-задание не попадают токены Telegram/МойСклад, пароль БД или auth.json.
Попадают бизнес-показатели и, когда это важно для действия, названия товаров,
складов, документов и клиентов возможного оттока.

## Режимы

- `AI_ANALYST_MODE=off` — полностью выключено.
- `AI_ANALYST_MODE=shadow` — анализ выполняется и сохраняется, но не отправляется.
- `AI_ANALYST_MODE=live` — проверенная сводка отправляется после PDF.

Вопросы работают только в `live`. Одновременно от одного пользователя
обрабатывается один вопрос; следующий получает понятное сообщение ожидания.

Первые семь дней production должен работать в `shadow`. Перевод в `live` —
только после просмотра сохранённых результатов и ложных срабатываний.

## Авторизация без API-ключа

Авторизация выполняется один раз от пользователя `hermes-ai`:

```bash
sudo -u hermes-ai -H env CODEX_HOME=/var/lib/hermes-ai/.codex \
  codex login --device-auth
```

`/var/lib/hermes-ai/.codex/auth.json` должен принадлежать `hermes-ai` и иметь
права `0600`. Файл нельзя копировать в репозиторий, логи или Telegram.

## Сервисы

- `hermes-ai-worker.service` — постоянный изолированный worker.
- `hermes-ai-daily.timer` — в 08:30 Europe/Moscow запускает `ai-daily`.
- `python -m hermes ai-daily` — два утверждённых PDF и один объединённый анализ.

Если Codex недоступен или лимит подписки исчерпан, основной PDF продолжает
работать. В `live` бот пишет только: «ИИ-анализ временно недоступен. Основной
PDF сформирован корректно».
